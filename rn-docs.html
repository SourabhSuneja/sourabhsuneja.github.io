Version Control
Push Local Changes to GitHub
Clone, stage, commit and push your project to the remote repository.
1
Clone the repository Only needed once if the repo isn't already on your machine.
bash 
git clone https://github.com/SourabhSuneja/jvp-attendance-tracker.git
2
Copy project contents into the cloned folder Paste all your project files into the local repository folder.
3
Stage all changes
bash 
git add -A
The -A flag stages all changes — new files, modifications, and deletions.
4
Commit the staged changes
bash 
git commit -m "Commit message"
5
Push to GitHub
bash 
git push
This pushes to origin (the original GitHub remote) by default.
Android Production Build
Install Dependencies & EAS CLI
One-time setup before your first build.
1
Install project dependencies Run once after cloning or setting up the project.
bash 
npm install
2
Install EAS CLI globally One-time install on your machine. Skip if already installed.
bash 
npm install -g eas-cli
3
Log in to your Expo account
bash 
eas login
4
Check dependencies (optional but recommended)
bash 
npx expo-doctor
This checks that all Expo dependencies and native modules are correctly configured.
Configure app.json
Set app name, icon, splash, package name, and version before each build.
Keep one master icon assets/app-icon.png at 1024×1024 px. It serves as the app icon, adaptive icon foreground, and splash image.
Before every new build, update version and android.versionCode.
1
Open app.json and edit the fields below
app.json 
{
  "expo": {
    "name": "JVP Attendance Tracker",
    "slug": "snack-72236e1f-5322-4e6b-af86-34877faea0f8",
    "version": "1.0.2",          // bump this each release
    "orientation": "portrait",
    "icon": "./assets/app-icon.png",
    "userInterfaceStyle": "light",
    "newArchEnabled": true,
    "experiments": {
      // MUST match the exact subpath where the web app is hosted
      "baseUrl": "/attendance-tracker/web-app"
    },
    "splash": {
      "image": "./assets/app-icon.png",
      "resizeMode": "contain",
      "backgroundColor": "#ffffff"
    },
    "ios": { "supportsTablet": true },
    "android": {
      "package": "com.jvp.attendancetracker",
      "versionCode": 3,            // increment this each release
      "adaptiveIcon": {
        "foregroundImage": "./assets/app-icon.png",
        "backgroundColor": "#4F959C"
      },
      "edgeToEdgeEnabled": true
    },
    "web": { "favicon": "./assets/app-icon.png" },
    "extra": {
      "eas": { "projectId": "cd51fb7c-ed31-4fa6-8ed8-9500b6f8a0db" }
    },
    "plugins": ["expo-font"]
  }
}
The experiments.baseUrl must exactly match the subpath of your web host. If hosted on GitHub Pages, also add a .nojekyll file to the root of your server.
Configure EAS Build (eas.json)
Set up build profiles for AAB (Play Store) and APK (testing).
1
Run the configure command
bash 
eas build:configure
2
When prompted, choose:
  • PlatformAndroid
  • Profilemanaged
This creates eas.json in your project root.
3
Verify / edit eas.json to match this structure:
eas.json 
{
  "build": {
    "production": {
      "android": { "buildType": "app-bundle" }  // AAB for Play Store
    },
    "apk": {
      "android": { "buildType": "apk" }         // APK for testing / sharing
    }
  }
}
Set Up Keystore & Credentials
Sign your app with your own keystore before submitting to Play Store.
1
Place the keystore file in the project root
Copy android.keystore into the root folder of your project (same level as package.json).
2
Run the credentials command
bash 
eas credentials
3
When prompted, choose:
  • PlatformAndroid
  • ActionUpload my own keystore
Build the App (AAB / APK)
Trigger a cloud build — outputs AAB for Play Store or APK for direct install.
A
Build AAB — for Google Play Store
bash 
eas build -p android --profile production
B
Build APK — for testing / direct sharing
bash 
eas build -p android --profile apk
Builds run on Expo's cloud servers. You'll get a download link when it's done — no need to keep your terminal open.
Releasing App Updates
Bump the version and versionCode before building a new release.
1
In app.json, increment both version fields
app.json — android section 
"version": "1.0.2",         // human-readable version string
"versionCode": 3            // must be a higher integer than the previous build
versionCode must always be higher than the previously uploaded build on the Play Store. It's an integer — never reuse or decrement it.
2
Run the build commands again
bash 
eas build -p android --profile production
Web Export
Build & Deploy the Web App
Install web dependencies, test locally, export to dist/, and upload to your host.
1
Install web dependencies One-time only — skip on subsequent builds.
bash 
npx expo install react-dom react-native-web
2
Test in the browser before building
bash 
npx expo start
After the dev server starts, press w in the terminal to open the app in your browser. If it looks and works correctly, you're ready to build.
3
Build for production
bash 
npx expo export --platform web
4
Upload output to your hosting provider
The build output is in the dist/ folder. Upload all its contents to your web host (e.g. GitHub Pages).
If hosting on GitHub Pages, add an empty .nojekyll file to the server root so that asset paths with underscores work correctly.
